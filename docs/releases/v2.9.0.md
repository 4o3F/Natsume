# v2.9.0

**Client 增加离线诊断证据、可扫码的原生全屏诊断页，以及统一的黑白全屏界面。**

## 主要变化

- Daemon 在运行时发布独立的最近报告和保留的最近失败，记录硬件身份来源状态、启动阶段、网络观测、连接尝试和注册握手里程碑。不包含硬件原始值、源哈希、秘密、配置正文、任意异常文本或日志。
- Helper 的机器身份推导返回脱敏来源报告，保留原有来源 quorum、派生算法和 identity-before-credentials 门禁。注册握手拆分为具体阶段，不改变 Server Device Control 协议、TLS 校验、注册权限或重试语义。
- Agent 使用可信、有界、只读的报告消费和离线二维码。报告仍是历史证据，不证明当前进程存活、授权或安全；没有可用报告时只显示明确标识的有限 Agent 本地观察。
- Binding、Waiting 和诊断采用统一横向页头与黑白网格，随窗口等比缩放。长名称可完整阅读，座位独立可见；作者头像保持圆形，按实际物理显示尺寸和 DPI 使用 Lanczos3 下采样。
- 诊断不会覆盖 Binding、已绑定队伍或恢复后的在线快照，不抢输入焦点，不增加 Daemon→Agent ACK、启动排序或退出等待。健康诊断页沿用真实原生 Waiting 首帧确认，不因报告分类误耗 Waiting 恢复预算。

## 升级说明

不增加数据库 migration，不修改 Server Device Control 或部署配置格式。Client 包中的 Daemon、Helper、Agent 应作为同一版本整体升级；Helper 的 `DeriveMachineIdentity` 本地 D-Bus 返回值已扩展为结构化报告，不应混用旧版调用方与新版 Helper。包内 tmpfiles 和 systemd 设置提供只读消费所需的 `/run/natsume-diagnostics` 运行时目录；报告不写入持久化数据库。

二维码包含有限的设备和连接诊断元数据，请按现场运维资料处理。最近报告与历史失败不拼接；历史 `active`、重试状态和等待时间不作为实时健康判断或倒计时。

## 验证范围

本地开发定向验证通过 Agent 25 library + 5 binary tests、Daemon Waiting 14 tests、Clippy、格式和 diff 检查，六个 `prek run --all-files` hooks 全部通过。离屏二维码截图 18/18 解码及 JSON 比对通过；同窗口尺寸／DPI 往返、头像缓存和页眉分隔线几何检查通过。独立安全、UI 和生命周期审查未发现未解决问题。

这些结果不替代真实 Skia/Wayland Kiosk、物理键鼠／IME／无障碍、HiDPI 显示模式变更、手机现场扫码或目标镜像验收。完整发布 CI 在 tag 推送后执行，全部通过后才自动发布产物。
