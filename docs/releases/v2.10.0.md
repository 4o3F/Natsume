# v2.10.0

**Client 修复呈现 revision 切换时的两处竞态，放大学校展示区域，并改善校徽缩放质量。**

## 主要变化

- Agent 的旧帧确认被新 UI revision 淘汰时，仅在原有效 lease／session 上取得严格更新的鉴权快照后刷新画面，不因正常 supersession 立即断开、重新注册。沿用原 lease deadline；拒绝的旧帧不被接受，新画面仍需真实首帧确认。其他拒绝、身份不符、过期／替换 lease、快照读取失败或 revision 未推进仍 fail closed。
- Daemon 不再仅因替换首帧尚未到达就撤回 Binding eligibility、再次推进 revision。真实 waiting OS、认证 Agent、前台、contest、Home、Target／epoch 条件失效仍撤权；提交、维护和就绪仍要求当前 revision 的真实全屏帧。保留既有 60 秒恢复冷却、45 秒最大观测间隔及 Helper 每 boot 恢复预算。
- 绑定后取得的新 Waiting 快照完整保留队名、校名、座位和 Logo；本地 RPC 日志使用固定操作名及有界错误类别，不输出异常 payload。
- 按 1920×1080 设计基准，将校徽显示区域增至 192×192、中文校名字号增至 84、英文校名增至 40，学校区域增至 216 高；图文整体居中，队伍／座位区下移 80，其他分辨率等比缩放。
- 校徽保留原始像素，按实际物理尺寸／DPI 用 Lanczos3 重采样，等比完整显示而不裁切。透明边缘使用预乘 alpha 并保留滤波余量，避免杂色和非饱和颜色变亮；同尺寸复用缓存，换图／回退不会恢复上一所学校的校徽。默认 SVG 保留矢量路径。

## 升级说明

不增加数据库 migration，不修改 Server Device Control、本地 D-Bus 方法签名或部署配置格式。Client 包中的 Daemon、Helper、Agent 仍应作为同一版本整体升级；本次发布包含 v2.9.0 之后的呈现竞态及 UI 修复，不应继续使用旧 v2.9.0 Deb 进行这些修复的验收。

可以先在现有系统重装 Client Deb，确认 Waiting 稳定性、绑定后资料与校徽显示，再重建完整镜像。诊断报告可读或历史 `active` 不代表当前 Device1 健康；可信读取器仍拒绝可写父目录，包括用于 UID 解析的 `/etc/passwd` 父目录。不要通过放宽文件信任检查或首帧／授权门禁掩盖现场故障。

## 验证范围

- `cargo test -p natsume-session-agent --locked`：30 library + 10 binary tests 通过；包括 5 个校徽重采样测试，以及同 lease supersession、绑定后 Waiting 资料和期限／身份／拒绝负向回归。
- `cargo test -p natsume-device-daemon reconcile:: --locked`：91 通过、1 个既有 packaged Caddy 环境依赖测试忽略。覆盖暂停新帧时资格／revision 稳定、真实条件失效撤权、就绪／维护门禁与恢复健康回归，不宣称忽略项通过。
- `cargo test -p natsume-server openapi --locked`：16 library + 1 exporter tests 通过；`cargo run -p natsume-server --bin export-openapi --locked`、`pnpm api:generate` 与 `pnpm --filter @natsume/web openapi:lint` 通过，TypeScript schema 无接口变化。
- `cargo fmt --all --check`、`git diff --check` 与 `bash -n packaging/ci-package-smoke.sh` 通过；六个 `prek run --all-files` hooks 全部通过。
- 软件离屏检查覆盖 1920×1080、1280×800、HiDPI，校徽尺寸 192→128→384→192 往返保持原始采样结果、同目标缓存、非方形新校徽及 SVG 回退。独立审查发现的 alpha 滤波颜色偏差已修复并复查通过。

首次版本升级后的 Agent 验证因本机构建磁盘耗尽而链接失败；仅清理可重建的 Cargo 缓存后，同一命令通过。上述结果不证明现场切屏的唯一原因或实际机器已经恢复；RPC 测试服务和预鉴权 fixture 不等同于真实 logind／SubmitBinding／compositor 的联合验收。真实 Skia/Wayland、显示模式变更、最大源图重采样延迟及完整镜像仍待现场验证。低清原图无法由重采样恢复丢失细节。

完整发布 CI 在 tag 推送后执行，全部通过后才自动发布产物；本说明不预先宣称发布 CI 通过。
