# v2.7.0

**Web 面板新增用户管理、邀请注册与密码恢复。**

## 主要变化

- admin 的 Users 页面支持查看用户、指定 admin/viewer 角色、删除用户及管理注册邀请。所有 admin 权限平等，最后一个已注册 admin 不能删除或降级；有其他 admin 时允许自我删除或降级。
- 新用户只通过注册链接自行选择唯一用户名并设置密码，管理员不代设密码。邀请固定角色、有效期七天、成功注册后只能消费一次；支持撤销和重新生成，旧链接随重新生成失效。
- admin 可为已有用户生成一小时有效的密码重置链接。生成不影响旧密码或会话，替换使旧链接失效；成功设置新密码后撤销目标用户的全部会话和恢复授权。
- admin/viewer 均可验证当前密码后修改本人密码。注册和链接重置必须先退出当前登录，成功后返回登录页，不自动登录。管理员失权会撤销其未使用的邀请和恢复链接；用户删除、角色变化和密码吊销对后续新请求生效。
- 链接明文只在签发时展示并可复制，使用当前面板 origin 和 fragment 携带授权；匿名页面读取后清除 fragment，通过 JSON body 检查和提交。Operator API 响应统一 no-store，包括请求体超限等外层拒绝。
- 新密码为 16～1024 位 ASCII，只允许英文字母、数字和以下特殊字符，至少包含一个数字和一个特殊字符，禁止空格。已有密码仍可登录或用于当前密码验证；新策略适用于注册、改密、链接恢复及 TTY bootstrap/reset。

```text
!@#$%^&*()-_=+[]{};:,.?/~
```

本版本还包含自 v2.6.0 以来的设备 IP 记录和应急地址导出、设备详情行内展开，以及 Waiting 页面品牌与作者头像展示更新。设备页区分 Server 观测地址与 Client 报告地址；应急导出使用全量非撤销设备的持久化 Server 观测 IP，不受页面筛选影响。

## 升级与恢复

Server 启动时自动应用设备网络记录和 Operator 链接的增量 migration，保留已有 Operator UUID、密码、会话及比赛/设备数据。已有部署无需重新 bootstrap；在维护窗口备份数据库及配置/密钥后升级配套包并重启服务，使运行进程加载新版本。设备地址报告与 Waiting 展示需要新版 Client；不修改部署配置格式或增加新的 Device Control/本地 IPC 协议版本。

唯一 admin 无法登录时，沿用 Server 本机交互式 TTY 命令 `sudo -u natsume-server -- /usr/bin/natsume-server reset-operator-password`。成功重置会撤销该账户的全部会话和 Web 恢复授权。回退遵循已有[部署运维手册](../operations-deployment.zh-CN.md)中的备份恢复流程；恢复旧数据库快照可能恢复快照中的旧授权事实。

本地验证包含域/HTTP 自动测试、105 项 mock 浏览器回归及隔离生产 Server 的真实 HTTPS/cookie 注册、改密、恢复、权限和删除全流程。实际部署升级、重启、TTY 恢复及备份恢复演练未执行；发布 tag 和 CI 不代表这些现场验收已完成。
