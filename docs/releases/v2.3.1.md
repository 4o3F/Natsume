**修复 Client 的 Gateway 本机解析和 Firefox 入口：启动时直接使用 `config.toml` 中的域名。**

## 主要变化

- Device Daemon 解析 `[site].gateway_hostname`，通过固定 D-Bus 能力传给 Privileged Helper。Helper 只校验域名并执行本机文件操作，不读取 Client 配置。
- 自动维护 `/etc/hosts` 的 IPv4/IPv6 loopback 映射，同步 Firefox 主页、`Contest Site` 工具栏书签和已有的相关通知许可；无需在镜像中烘焙赛事域名。
- 改名清理旧受管记录，保留其他 hosts 别名、Firefox 策略、书签与 CA。重复启动不重写未变文件，损坏输入会明确拒绝。
- 同步在控制连接前完成，不依赖 Server 在线或 Enrollment，也不修改 teams Home。部署及镜像交接文档同步更新。

## 升级

从 v2.3.0 升级无需重做镜像，也没有新增数据库 migration 或控制/Agent 协议变化。维护期安装完整 Client Deb 后执行：

```sh
sudo systemctl restart natsume-privileged-helper.service natsume-device-daemon.service
```

随后完全退出再打开 Firefox。保留设备身份、凭据、绑定、Home 状态、现有配置与 CA；不要重新 bootstrap 或删除数据库。Server 若一并升级，安装新包后显式重启服务。

后续修改域名时，保持两端配置一致，重启 Device Daemon 并重新打开 Firefox。更早的 X11 Client 仍须完成原生 Wayland 镜像配置迁移。

具体步骤见[部署与升级手册](https://github.com/4o3F/Natsume/blob/v2.3.1/docs/operations-deployment.zh-CN.md#upgrade-v2-3-1)。
