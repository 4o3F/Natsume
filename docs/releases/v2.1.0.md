**Breaking Change（BC）：v2.1.0 必须配套升级 Server 和 Client，不能混用旧控制／本地 IPC 契约。**

## 主要变化

- 统一导入完整 XLSX 队伍名单，自动生成稳定的 INST 学校 ID；旧 CSV 入口移除。每次导入均为完整名单，只有实际变化的密码推进凭据版本。
- Server 从按校名保存的本地目录提供 Logo，按内容识别 PNG、JPEG、WebP、SVG。DOMjudge 导出为包含 JSON／YAML、说明及全部可用 INST 命名 PNG 的完整 ZIP。
- waiting 显示学校 Logo、双语队名／校名和座位，支持非秘密离线缓存；解绑清除旧资料，换绑拒绝迟到图片。座位绑定页使用暖色双栏和可读错误提示。
- Web 设备表分列显示收敛状态、绑定与座位，区分离线／禁用，支持座位排序与保留刷新位置；Accounts／Seats 展示队伍、学校和 Logo。
- Provisioning window 开启时自动批准 Enrollment，关闭时等待管理员审批。新设备以前台 waiting 为默认目标；绑定后等待管理员切换到比赛桌面。

## 不兼容项与升级顺序

1. 在维护窗口完成现有 Home／会话操作，备份数据库、密钥、配置和 Client 状态，停止 Client 控制连接。
2. 升级 Server，在现有 `config.toml` 的 `[storage]` 中设置必填绝对路径 `organization_logos`。保留原数据库与密钥，不重新 bootstrap。
3. 启动 Server 自动迁移数据库，再导入完整 XLSX，按原账号／座位补齐现有绑定对应的队伍和学校资料。旧的未提交导入候选需重新上传。
4. 升级同版本 Client（Daemon、Helper、Session Agent）及随包交接输入；先验证一台设备，再逐批恢复。

控制连接现使用 `natsume.control.v3`，本地 Session Agent 注册使用协议 3。协议编号与本次软件版本号独立；缺少必需队伍资料的绑定目标会被拒绝。由 v2.0.4 升级时保留已有设备身份和绑定，不能删除身份文件来绕过错误。

详细步骤见[配套升级手册](https://github.com/4o3F/Natsume/blob/v2.1.0/docs/operations-deployment.zh-CN.md#upgrade-v2-1-0)。回退必须使用同一维护点的旧包、数据库、密钥与配置，不能混用新旧状态。
