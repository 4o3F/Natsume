# v2.6.0

**Client 新增 DOMjudge 命令行提交所需的 API 自动认证与动态提交地址。**

## 主要变化

- 本机 Caddy 在 READY 时为 `/api/*` 注入当前 Binding 队伍的 HTTP Basic 认证，覆盖请求自带的 Authorization，并清除 Web 登录专用的 `X-DOMjudge-*` 头。`/login` 保留原有自动登录行为。
- API 访问沿用现有 Binding 凭据更新、解绑和 READY/BLOCKED 收敛，不增加 Server 配置或另存 CLI 密码。
- Daemon 启动时通过现有 `ConfigureLocalGateway` 同步公开提交地址。Helper 原子生成 root:root/0644 的 `/etc/natsume/submit.env`，内容为 `SUBMITBASEURL='https://<gateway_hostname>/'`，不含账号密码。
- 域名变更、重复启动和中断恢复与现有 hosts/Firefox 配置一同处理；提交配置独立于 teams Home，重复启动不重写内容和权限均未变的文件。

## 升级与镜像配合

本次没有数据库 migration、Device Control 协议或本地 IPC 参数变更，无需重新注册设备或重建 Binding。升级 `natsume-client` 后重启 Device Daemon 与 Privileged Helper，使运行进程加载新版本并生成公开提交配置。

镜像还需提供读取该配置的 `submit` 启动器和固定版本的上游脚本。**这些镜像改动全部在 `310-natsume` 中完成**：独立声明并锁定上游脚本资产，通过该模块的 rootfs 覆盖公开 `submit` 入口与旧 profile 默认值；保留 `160-contest`、base 和其他安装源。

启动器每次读取 `/etc/natsume/submit.env`，以系统 Python 执行上游脚本，仅为该进程设置 Local Origin CA 的 `REQUESTS_CA_BUNDLE` 和 Gateway 域名的代理绕过配置，原样传递参数及退出码。仅升级 Deb 不会自动替换镜像已有的 `submit` 命令。长期输入与验收契约见 [镜像输入](../../packaging/image/inputs.md) 和 [镜像验收](../../packaging/image/acceptance.md)。

本地测试已覆盖真实 Caddy 的认证头、路径边界、多文件 multipart 上传、改密和 BLOCKED，以及 Helper 配置与 IPC；真实镜像中无 `.netrc`、未登录 Firefox 的 teams 提交仍需与实际 DOMjudge 联调验收。打印部署不属于本次交付范围。
