**Breaking Change（BC）：Session/Home 目标写入统一使用 Server batch API，旧单台写入口移除。**

## 主要变化

- 新增 `POST /api/v2/target-submissions`。单台、全部 Enabled、失败设备重试共用资格检查和逐设备提交结果；全部设备范围由 Server 写事务确定，包含离线设备。
- 操作 ID、规范化请求和结果持久化去重。设备级拒绝允许部分成功；数据库写入或提交失败则整批回滚。事务只处理 Server 状态，不等待 Client converge。
- Web 保留一个待确认提交，刷新后可用原 ID 手动安全重试；明确拒绝的设备可使用新 ID 仅重试失败名单。
- Targets 展示全部设备、座位与 Session/Home 状态，支持搜索、排序、单台操作和批量操作；Bindings 按座位定位并完整显示 Device UUID。
- Web 图标统一使用 Lucide，导入预览表格固定表头并保持横向对齐，自动刷新保留滚动位置。
- Server Deb 自动创建 `/var/lib/natsume-server/organization-logos`，保留已有图片；OpenAPI 导出命令提供默认输出路径。

## 从 v2.1.0 升级

1. 暂停新操作，冷备份数据库、密钥和配置，保留原安装包。
2. 安装 `natsume-server_2.2.0_amd64.deb`，显式重启 Server。启动时自动新增去重记录表，保留既有数据；不要重新 bootstrap。
3. 完全刷新管理员 Web。自定义脚本将旧 Session foreground、terminate、Home reset 写接口迁移到统一提交 API；原读取接口保留。
4. 核对一台设备的目标提交及实际收敛，再使用批量操作。结果不明时重试原请求，不生成新 ID；明确拒绝项可单独发起新提交。

控制连接仍为 `natsume.control.v3`，本地 Agent 协议仍为 3；v2.1.0 Client 可继续连接。由 v2.0.x 升级仍须执行控制协议与队伍资料的配套升级步骤。

详细步骤见[最新部署与升级手册](https://github.com/4o3F/Natsume/blob/v2.2.0/docs/operations-deployment.zh-CN.md#upgrade-v2-2-0)。回退使用同一维护点的包与数据库；不能向回退后缺少新去重记录的系统重放升级后的请求。
