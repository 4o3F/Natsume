# v2.10.2

**修复 Client Waiting 中文队名的字形重叠。**

## 主要变化

- 将 HarfRust 固定到上游 [16 位缓存修复提交](https://github.com/harfbuzz/harfrust/commit/0149dc8b9376caabd803c12ff3cc08be32242597)，保留 Slint 1.15.1、Parley 0.7.0 和 HarfRust 0.3.2 的版本组合。修复前，部分 Noto CJK 字形会把空缓存项误当作字形属性，导致普通汉字被标为组合附加符号、前进宽度清零；例如“东北大学_到达胜利前无法回头”中的“胜”和“利”因此重叠。
- 不修改 Waiting 的字体大小、字距、换行或滚动布局。恢复正确字宽后，队名按正常测量结果换行。
- 依赖策略只允许明确的 HarfRust 上游 Git 仓库，并要求 Git 依赖指定 revision；不放宽未知来源检查。
- 为现有 `zip@8.6.0` 增加精确版本的临时撤回状态豁免。已发布的 Calamine 0.36.1 仍要求 ZIP 8，目前没有已发布的 ZIP 9 兼容版本；本次不迁移 ZIP／Calamine、不引入额外解析器改动。其余撤回版本和 RustSec 安全公告仍按原策略检查，待 Calamine 发布兼容支持后移除此豁免，每次 ZIP／Calamine 依赖更新时重新审查。

## 升级说明

不增加数据库 migration，不修改 Device Control、本地 D-Bus 方法签名或部署配置格式。升级 Client 后重启 Session Agent 或正常重启比赛工位即可使用修复后的文字整形。Server 同步使用 2.10.2 版本号，HTTP API schema 不变。

## 验证范围

- `cargo tree -p natsume-session-agent --locked -i harfrust`：确认 Parley 使用固定到上述完整 revision 的 HarfRust，未同时保留原 crates.io 副本。
- `cargo test -p natsume-session-agent --locked ui::tests`：6 项通过，覆盖队名字号、单语言展示、Binding 输入条件及首帧几何确认。
- 对锁定的上游缓存源码进行 6 项定向检查：16 位缓存高位字形 ID 的空槽、正常命中、槽位冲突、空值编码碰撞，以及 32 位缓存行为均通过。原版依赖在其中 2 项失败。
- 使用项目 `SessionWindow`、Skia 和 Noto Sans CJK SC，在 1920×1080 原生窗口中渲染上述队名，确认“胜”和“利”分开，末字按恢复后的正确宽度换行。此开发环境检查不代表真实 Kiosk、HiDPI 或现场镜像已验收。
- `cargo test -p natsume-server --locked openapi`：16 项 library 测试及 1 项 exporter 测试通过。OpenAPI 导出、`pnpm api:generate`、`pnpm --filter @natsume/web openapi:lint` 通过；OpenAPI 仅版本信息变化，TypeScript schema 无接口变化。
- `cargo fmt --all --check`、`git diff --check`、`bash -n packaging/ci-package-smoke.sh` 通过；工作区、7 个本地 crate、OpenAPI 与 CI／打包默认版本均为 2.10.2。ZIP／Calamine 的锁定版本、来源和依赖保持不变。
- 初次依赖检查因既有 `zip 8.6.0` 已撤回而失败；加入上述精确版本豁免后，`prek run --all-files --skip rust-test --skip web-test` 的依赖安全、Web 格式、Web lint 和 Rust Clippy 检查均通过。完整 Rust／Web 测试套件留给 CI，未在本地运行。

完整发布 CI 在 tag 推送后执行，本说明不预先宣称其通过。发布 Deb 和真实比赛镜像仍需各自验收。
