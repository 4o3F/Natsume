**Client 图形栈迁移：waiting 和 teams 改用 GDM 管理的原生 Wayland 会话，升级须配套应用镜像配置。**

## 主要变化

- waiting 使用官方 GNOME Kiosk Wayland，teams 使用完整 Ubuntu/GNOME Wayland，避免原物理 Xorg/GLX 连接在后台暂停时阻塞 GNOME 主循环的路径。普通切换保留两个会话，Xwayland 继续提供 X11 应用兼容。
- Session Agent 使用 Wayland 后端，依据 compositor 确认的全屏状态、输出尺寸和实际帧报告展示就绪。
- Helper 在固定用户身份下核对 compositor、Wayland 输出与输入能力；激活后有界确认异步恢复。暂时不可用不再使桌面准备提前结束，精确会话变化或持续故障仍明确失败。
- 后台 waiting 暂欠新帧时允许先激活再确认；单纯后台缺帧不消耗 waiting 重建预算，Home 维护仍要求当前前台帧。
- GDM 登录增加真实注册回执与精确 greeter 身份核对，并记录准备阶段，继续使用固定 PAM 和 Home 门禁。初始化及 Home reset 仍可能短暂显示 greeter、黑屏或闪屏。
- 镜像交接同步 Wayland 会话入口、GDM 配置与 VT 快捷键策略，移除旧 Natsume Xorg ServerFlags 和 Kiosk X11 frame-scale 输入。

## 从 v2.2.x 升级

本次没有新增数据库 migration，Device Control 与本地 Agent 协议不变；现有协议兼容的 Client 可继续连接新 Server。

Client 升级必须在维护期完成：保存比赛数据，安装完整 v2.3.0 Client，应用 `/usr/share/natsume/image-integration/` 中的配置，清理强制 X11 的旧覆盖，然后正常重启。确认 waiting/teams 的实际 `Type=wayland`，并验证显示、输入、切换及 Home reset。

通用 Deb 不会自动迁移上游 GDM/dconf 配置，也不会保证已有进程重新加载；仅替换 Deb 不足以完成图形栈迁移。设备身份、凭据、绑定和 Home 维护状态应保留，**不要重新 bootstrap 或清除数据库**。

具体步骤及更早版本升级路径见[部署与升级手册](https://github.com/4o3F/Natsume/blob/v2.3.0/docs/operations-deployment.zh-CN.md#upgrade-v2-3-0)。
